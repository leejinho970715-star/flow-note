# Flownote — 주간보고 자동화 샘플 / 고객 맞춤 템플릿

2026-10-27 KST. `/`는 브라우저 CSV 체험판, `/workspace`는 계정·회사 격리·SQLite 저장이 있는 로컬 운영판이다. 입력 샘플은 전부 가상이다. 광고 API, 외부 AI 호출, 예약 실행, 메일 발송, 결제·회계는 연결하지 않았다.

## 새 워크스페이스 실행과 운영

Node 24에서 `npm run demo:report` 실행 후 http://127.0.0.1:3002/workspace 접속. `가상 자료로 워크스페이스 체험`은 새 가상 회사와 샘플 작성자의 검수 대기 보고서를 생성한다. 체험 계정은 로그아웃 후 복구하지 못한다. 실제 지속 사용은 별도의 회사 계정을 생성한다. 이메일 소유 확인·비밀번호 복구·SSO는 제공하지 않는다.

1. 고객·프로젝트에서 고객 ID, 캠페인, 기간과 담당자를 연결한다.
2. 새 보고서에서 CSV를 선택하고 자료·연결 검사를 실행한다. 가상 샘플 버튼은 10월 19~25일 자료를 넣는다.
3. 고객·기간·집계값과 제외 행을 확인한 후 초안을 저장하고 검수를 요청한다.
4. 작성자와 다른 관리자 또는 검수자가 해당 버전을 승인한다. 직접 작성한 보고서는 승인할 수 없다.
5. 승인본 HTML/CSV를 다운로드한다. 전달 수동 기록은 메일 발송이나 고객 수신 확인이 아니다.
6. 다른 파일로 수정하면 새 버전에서 다시 검수한다. 이전 승인본은 변경하지 않는다.

관리자(owner)는 고객·프로젝트·팀을 관리하고 작성·검수할 수 있다. 작성자(editor)는 초안을 만들고 검수를 요청한다. 검수자(reviewer)는 타인의 보고서를 검수한다. 역할과 회사 권한은 서버가 다시 검사한다. 세션·CSRF·동일 출처 검사, 미승인 다운로드 차단, 중복 파일 차단, 미리보기와 저장 대상의 서명 검증을 적용했다.

DB는 `data/flownote.sqlite`이며 원래 회사 시스템 DB와 분리된다. 원본 CSV 본문은 영구 보관하지 않고 선택 고객의 보고 결과·일부 원본 대조 자료·파일 해시·매핑·검수 기록을 저장한다. 예외 사유와 승인 내역도 보관한다. 원본 파일 전체의 완전성은 판별하지 못한다.

백업: `npm run flownote:backup`. 복원: `npm run flownote:restore -- "백업 파일의 절대 경로"`. 복원은 새 DB 파일만 만들며 운영 DB를 덮어쓰지 않는다. 확인한 복원본은 서버를 중지하고 `FLOWNOTE_DB`로 선택한다. DB에는 모든 회사의 자료가 있으므로 운영자만 파일을 취급한다.

사용 가이드 16개와 검색형 도움말을 제공한다. 질문 답변은 매뉴얼 기반 규칙 검색이며 LLM 대화·회사 자료 검색·업무 실행 기능은 아니다. Pretendard를 로컬 제공하고 화면·다운로드 보고서의 최소 글자 크기를 14px로 맞췄다. 폰트 라이선스는 assets/Pretendard-LICENSE.txt에 있다.

검증(2026-10-27): 전체 테스트 51개, 타입 검사, 프로덕션 빌드 통과. 실제 로컬 HTTP 통합 검사에서 등록·세션·매핑·초안·자기 승인 차단·타인 승인·회사 격리·다운로드·새 버전·중복·CSRF·로그아웃을 확인했다. 브라우저에서도 초안 저장→검수 요청과 다른 작성자의 승인·감사 기록을 확인했다. 실제 고객 자료·공개 운영 보안·외부 연동·고객 지불 의사는 미검증이다. 서버는 loopback 전용이며 인터넷 공개 배포용으로 검증하지 않았다.

## 실행·고객 시연

- 로컬 실행: ai-universe 폴더에서 `npm run demo:report`, http://127.0.0.1:3002/ 접속.
- 서버 없이: `flownote-demo.html`을 브라우저에서 연다. CSS·계산 코드·샘플을 포함한 단일 파일이며 고객 제시용 사본으로 전달 가능하다. 내장 스크립트 구문·외부 참조 제거를 확인했으나, 인앱 브라우저의 file 프로토콜 제한으로 파일 직접 열기 동작은 검증하지 못했다. 브라우저 동작 검증은 HTTP 로컬 서버 버전에서 수행했다. 이 파일 전달/공개 게시 자체는 이번 작업에서 수행하지 않았다.
- 코드 수정 후 단일 파일 재생성: `node demos/weekly-report/build-standalone.mjs`.
- 화면의 샘플 CSV 다운로드 → 열 구조 확인 → 같은 양식의 익명 파일 선택. 샘플은 시작 시 자동 실행된다.
- 검수 내역에서 제외 이유를 확인한다. 일부 행이 제외되면 확인 체크 전 다운로드를 막는다. 수치가 충돌하는 중복·구조 오류는 전체 파일을 중단하고 이전 결과도 비운다.
- 고객사·시작일을 선택하면 해당 7일과 직전 7일을 집계한다. 고객용 HTML과 집계 CSV에는 선택 고객의 데이터만 포함한다. HTML을 브라우저에서 인쇄해 PDF로 저장할 수 있으나 자동 PDF 생성 기능은 아니다.

## 입력 계약

UTF-8 CSV, 2MB 이하, 15,000 데이터행 이하, 고객사3곳 이하. 필수 열은 순서를 바꿀 수 있으나 이름과 구성은 고정한다:

`date,client_id,client_name,campaign,currency,impressions,clicks,spend,leads`

- 날짜 YYYY-MM-DD, 통화 KRW만 지원. 지표는 음수와 천 단위 쉼표 없는 정수, spend는 소수 둘째 자리까지.
- 한 행은 고객ID·날짜·캠페인·통화별 집계값. 같은 키와 같은 값은 중복으로 제외, 같은 키에 다른 값은 파일 전체를 차단. 같은 날짜의 캠페인별 분할 행을 합산해야 하는 원본은 사전에 변환 규칙을 합의해야 한다.
- 원본 파일에 없는 행·일자·광고 계정은 알 수 없다. 파일의 완전성이나 업무상 의미를 자동 검증했다고 주장하지 않는다.
- CTR=총클릭/총노출, CPC=총비용/총클릭, CPL=총비용/총리드. 행별 비율 평균을 사용하지 않고 0분모는N/A로 표시. 비용은 정수 최소단위로 더한다.
- client_id는 영문·숫자·밑줄·하이픈40자 이하. 텍스트 필드는200자 이하. CSV 수식문자를 무력화하고 HTML을 이스케이프한다.

## 구현 범위·품질

core.js는 CSV 파싱·검증·집계·고객별 내보내기, app.js는 `/` 체험판 UI다. 이 체험판에서는 업로드 내용을 브라우저 메모리에서만 처리한다. `/workspace`는 별도의 서버 API와 workspace-store.mjs를 통해 인증·권한·서버 집계·영구 저장을 수행한다. 다운로드한 파일은 별도 사본이므로 사용자가 보관·삭제한다. 체험판의 고객 선택만으로 서버 권한이 생기는 것은 아니다. 실제 자료를 넣은 운영자 화면을 다른 고객에게 공유하지 말고 해당 고객의 승인된 내보내기 파일만 사용한다.

검증: 2026-10-24 `npm run typecheck`, `npm test`(전체38개·신규데모12개), `npm run build` 통과. 샘플18행=정상12+제외6, 라움리빙10/12~18 비용270,000원·클릭870·리드45·CPL6,000원. 브라우저에서검수탭·고객전환·ROI입력유지·제외확인후HTML다운로드·다운로드내용고객격리·잘못된CSV업로드후이전결과차단·샘플복원을확인했다. 성공업로드경로의모든브라우저/디바이스호환성과실고객파일은미검증.

초기테스트에서부동소수비율의엄격동등비교가실패해허용오차로수정했다. CTO검토로발견한ROI입력리셋, 미검수결과의검수완료표시, 비동기샘플의나중업로드덮어쓰기위험을수정했다. 공급자API·광고성과·고객지불의사검증은수행하지않았다.
