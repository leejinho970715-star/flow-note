# ENOTE-LABS product design guide

Company: ENOTE-LABS (이노트랩스). Product names remain Flownote, AgencyFlow, Follonote (팔로노트), Crewmemo (크루메모). Existing production URLs and authentication callbacks are unchanged.

## Shared workspace foundation

- Pretendard; minimum rendered UI text 14px, form input 16px, dashboard h1 29px.
- Shared orange `#c4541b`, warm ivory background `#fbf7f3`, white surface, ink `#382c24`, muted `#806e62`, border `#ecded3`, selected surface `#fff0e4`.
- Primary buttons use orange fill and white labels; secondary buttons use a neutral surface and full border. Active navigation has a filled region and full boundary. No decorative left-edge accent lines or rail divider.
- Cards use 12px rounding; inputs/buttons use 8-9px rounding. Status colors retain semantic distinctions.
- Dark mode uses warm brown neutral surfaces and a peach accent; primary buttons retain deep orange fill and white labels. The existing Flownote workspace remains light-mode only.
- Mobile navigation can wrap into two columns. Data tables/kanban may scroll within their own containers; the page itself must not overflow.

## Logos and marketing

The company retains orange `#ed7834`. Clean code-native SVG symbols identify each product: folded document (Flownote), feedback bubble (AgencyFlow), rising pipeline (Follonote), team (Crewmemo). Symbols appear at the left of each workspace header/rail and have matching PNG favicon variants and individual 1200x630 OG cards. SVG sources are generated by `scripts/enote-brand.mjs`; PNG/OG assets by `scripts/generate-product-guides.py`.

The marketing site uses orange-only accent/surface colors; product screenshots show the actual orange product UI, following the CEO's 2026-10-31 direction to unify dashboard colors. Four accessible product tabs switch the matching detail panel in place. Arrow keys, Home/End and URL fragments are supported; without JavaScript all four descriptions remain available. Mockups use code-native Mac-style chrome with three warm-tone controls, an address/title region and actual screenshot assets. The chrome is a visual mockup, not a claim of testing Safari or macOS.

Mobile marketing panels show the actual product screen before explanatory copy. GSAP ScrollTrigger replays staggered bounce/fade entrances on section entry/re-entry and panel selection. Highlighted phrases use a finite character reveal with a transient caret, while screen readers retain the full phrase. Reduced-motion preference removes movement and typing. Default HTML remains visible if JavaScript is unavailable. Screenshot source/date/view metadata is recorded in `studio/assets/capture-manifest.json`; captures contain fictional sample records only and are not recolored.

## Product guides

Four public `/manuals/{product}-guide.pdf` documents contain product introduction, getting started, a page for each major workspace screen, and current availability/limitations. Buttons labelled `제품소개서 보기` open them in a new tab from the company feature sections and each workspace. Documents use embedded Pretendard and 2026-10-30 availability statements.

Authoring: bundled Python + reportlab, pypdf, pypdfium2, fonttools, brotli, Pillow. Actual sample UI captures live in `docs/product-screens/`; run `scripts/generate-product-guides.py`, inspect all rendered contact sheets in `tmp/pdfs/`, then rebuild Next.js and the company target. Published PDFs live in `agencyflow/public/manuals/`; local delivery copies in `output/pdf/`. App functionality is not promoted to complete merely by documenting it.
