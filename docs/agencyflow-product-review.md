# AgencyFlow 제품·사업 진단 (2026-10-28)

## 판단

진행할 만한 가설이다. 그러나 “CRM부터 ERP까지 모두 대체”를 먼저 팔기보다 **웹에이전시·디자인 스튜디오의 고객 시안 검수와 최종 승인**에 집중한다. Flownote는 보고 자동화, AgencyFlow는 제작 피드백 협업, 회사 소개 사이트는 두 제품 및 맞춤 구축을 소개한다. 서로 다른 사이트·제품이며 현 단계에서 고객 DB를 자동 병합하지 않는다.

## 확인한 시장 사실과 아직 모르는 것

- Pastel 공식 가격: 월 결제 Pro $35/2명/활성 캔버스3개, Team $119/5명. 무료1명/캔버스1개, 고객 검토자 무제한. 이미지·웹 시안 피드백과 승인 제공. https://usepastel.com/plans
- BugHerd 공식 가격: Standard 월 $50/내부5명, 무제한 고객·프로젝트. 이미지·웹 피드백과 캡처 제공. https://bugherd.com/pricing
- Marker.io 공식 가격 문서: Starter 월 $59, 연 결제 환산 월 $39/내부3명, 고객·제보자는 무료. https://help.marker.io/en/articles/14625673-plans-and-pricing

위 사실은 이 문제에 돈을 받는 시장이 존재한다는 근거다. 국내 소형 에이전시의 구매율·시장규모·예상 매출을 입증하지 않는다. 실제 고객 인터뷰·유료 계약은 아직 없다. 무료 대안과 강력한 기존 제품이 있어 저가만으로 차별화할 수 없다.

## 첫 타깃과 메시지 (CMO 관점)

2~10인 웹에이전시·브랜딩/디자인 스튜디오, 동시에2개 이상 프로젝트 진행, 고객 수정 요청이 카카오톡·메일·캡처에 나뉘는 팀. 대형 ERP 교체 고객은 초기 대상에서 제외한다.

핵심 문구: “고객의 수정 요청을 시안 위에서 받고, 확인한 버전을 승인받으세요.” 고객에게 시스템 용어를 설명하지 않고 시안 위 클릭·답글·처리 상태만 보여준다. 소개 자료는 가상 샘플임을 밝힌다. 기존 툴보다 몇 시간을 절약한다는 검증 안 된 주장은 하지 않는다.

## 제품 범위 (CPO 관점)

1. 고객 등록·수정·보관, 프로젝트 연결·단계·일정
2. 이미지 시안 버전 업로드 → 정규화 위치 핀 → 댓글 → 처리 상태 → 고객 승인
3. 견적 수량·단가·난이도·기능 옵션 → 서버 합계 재계산 → 버전 → 고객 공개 → 승인 → 인쇄/PDF 저장
4. 작업과 프로젝트별 고객 접근 권한,14일 체험·서버 읽기 전용
5. 결제는 토스 준비 전까지 명시적으로 비활성화

“URL만 입력하면 모든 웹사이트 캡처”는 브라우저 same-origin·CSP·X-Frame-Options와 인증 세션 문제를 해결해야 하므로 MVP에서 제외한다. 이미지/스크린샷 업로드를 먼저 검증한다. 이후 설치 스크립트 또는 확장 프로그램·안전한 캡처 서버를 별도 과제로 만든다. 임의 URL 프록시와 SSRF 우회는 만들지 않는다.

전자서명·법률 검토 계약서, 정기 청구, 미수금·MRR 자동 계산, 유지보수 반복 일정, 이메일 자동 알림, 화이트라벨, 비회원 공개 링크는 구현 완료로 표시하지 않는다. 온라인 시안·견적 승인은 계약 전자서명이 아니다.

## 가격 가설

Lite 월9,900원/활성 프로젝트5/내부1명/1GB, Pro 월29,000원/활성20/내부3명/10GB, Agency 월99,000원/활성100/내부10명/50GB를 검증 가설로 제안한다(VAT 별도). 고객 검토자는 내부 좌석에서 제외한다. 체험은14일/최대100프로젝트·내부10명/시안1GB이다. 만료 시 데이터는 삭제하지 않고 읽기 전용이다. 결제로 자동 복구하는 흐름은 결제 연동 전까지 활성화하지 않는다.

원안의 29,000원 무제한 프로젝트·99,000원 무제한 사용자·화이트라벨은 저장/전송/지원 원가와 작업 범위를 통제하기 어렵다. 저장량·활성 프로젝트·내부 좌석을 명시한다. 현재의 저장공간 한도는 프로젝트/좌석과 별개이며 비용 계측 후 조정해야 한다. 유료 요금제의 유지 가능한 이익은 아직 검증하지 않았다. 호스팅·DB·파일 전송·SMTP·결제 수수료·고객 지원 시간을 실제 원가에 포함해야 한다.

## 30일 수요 검증

- 1~7일: 목표 고객10곳 인터뷰. 최근 실제 수정 요청/승인 지연 사례와 기존 도구·지출을 확인한다. 유입 숫자보다 반복 문제 여부를 기록한다.
- 8~14일:5곳에 가상 샘플 시연, 가능하면 익명화한 진행 프로젝트1개로 체험. 고객이 별도 설명 없이 핀을 남기는지 관찰한다.
- 15~21일:3곳 파일럿 목표. 수정 요청 누락, 재질문 횟수, 고객 참여율, 검수 완료 시간, 지원 소요시간을 도입 전후 비교한다.
- 22~30일:실제 결제 환경 준비 후 유료 전환 의향을 가격과 함께 확인한다. 2곳 이상이 월29,000원 수준의 유료 사용을 원하고 실제 고객 검수에 반복 사용하면 다음 개발 투자 가설을 지지한다. 이는 목표/판정 기준이며 달성 실적이 아니다.

고객이 새 로그인을 거부하면 권한·만료·회수 가능한 고객 초대 경험을 우선 개선한다. 견적 기능보다 실제 피드백 사용률이 낮으면 ERP 모듈을 확장하지 말고 핵심 흐름을 수정한다.

## 기술 구조 (CTO 관점)

Next.js16.4.3·React19.3.1·TypeScript7·Tailwind4 기반 정적 프런트, Supabase Auth/PostgreSQL/RLS/private Storage를 직접 연결한다. 공개 키만 번들에 포함한다. 비공개 시안은5분 만료 서명 URL로 조회하고 업로드는5MB PNG/JPEG/WebP이다. 회사별 잠금으로 쓰기·견적 버전·프로젝트/좌석/저장량을 확인한다. 고객은 지정 프로젝트만 접근하고, 내부 팀원은 고객 승인 권한이 없다. 승인 후 시안과 대화는 고정한다.

기존 Flownote 회사·보고서 테이블은 변경하지 않고 af_* 별도 테이블을 사용한다. auth.users는 같은 Supabase 프로젝트를 사용하나 로그인 저장 키와 업무 회사 공간은 분리한다. 운영자의 전체 회원/MRR 관리자 기능은 별도 보호 서버 설계 후 추가한다. 공개 브라우저에 service_role을 넣지 않는다.

실제 DB 트랜잭션 테스트에서 회사·고객 접근, 서버 견적 계산, 핀/답글/승인, 승인본 잠금, 체험 만료, 비공개 파일 격리를 검증했으며 테스트 자료는 롤백했다. 메일 인증·Toss 결제와 실제 고객 사용은 별도 미검증이다.
